SOC / Detection Lab

Active: adding techniques

A three-VM home SOC for practicing detection engineering. I stood up Wazuh as the SIEM, instrumented a Windows 11 endpoint with Sysmon, then ran MITRE ATT&CK techniques from Kali and worked each one as an exercise: did Wazuh catch it out of the box, and if not, what custom rule closes the gap?

TechniqueATT&CKDetectionRule
Port scan (Nmap)T1046Loggedn/a
RDP brute force (Hydra)T1110Custom: frequency100100 · lvl 10
Rogue admin accountT1136Out of the box60154 · lvl 12
Backdoor admin, correlatedT1136 / T1098Custom: correlation100200 · lvl 14
Encoded PowerShellT1059.001Out of the box92057 · lvl 12

A slow, spaced-out brute force set off only single failed-logon alerts (60122), so I wrote a frequency rule that turns 5 or more failures within 120 seconds into one level-10 alert, then reran the attack to confirm it fires. For persistence, I chained an "account created" event with an "added to Administrators" event into a single level-14 backdoor-admin alert. Along the way I fixed Wazuh services timing out on boot with systemd overrides, and caught Hydra reporting a false "valid password" by checking it against the logs.

phishscan

Published

A command-line phishing email analyzer in Python. Give it an .eml file and it parses the headers, links and attachments, runs 25+ detection checks, and returns a 0–100 risk score with a plain-English explanation of every finding. It only reads emails: it never opens attachments or visits links, and it prints every URL defanged.

$ python -m phishscan samples/test1.eml
Verdict: LIKELY PHISHING  (score 100/100)
  [HIGH  ] dmarc_fail: DMARC failed
  [HIGH  ] display_name_spoof: 'PayPal Support' on example.com
  [HIGH  ] double_extension: 'invoice.pdf.exe' is really .exe
  [HIGH  ] lookalike_domain: paypa1-secure[.]example[.]com imitates 'paypal'
  … 6 more findings
70%detection on a 50-email holdout set from the phishing_pot corpus
0false positives on 76 real legitimate emails after tuning
55pytest tests, run by GitHub Actions on every push

Checks cover SPF/DKIM/DMARC, sender mismatches, link text that points somewhere else, lookalike and punycode domains, throwaway TLDs and IP hostnames, and risky attachments, with optional VirusTotal lookups. Every tuning change is logged, and the 70% holdout number is the one I report because the rules weren't written against it.
